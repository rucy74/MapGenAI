# MapGen AI 텍스트 우선 개발 계획

2026-09-13. 사용자 결정: “이미지쪽은 나중에”, “텍스트 요청 먼저 전부 다 되게 만드는 걸 1차 목표”. 이후 “지금부터 fable 호출하지 말아줘. 된다고 할때까지. 크레딧이 없어서”로 **Fable 자문은 재허용 전까지 중단**했다. 이미지 코드는 유지하며 새 이미지 개선은 보류한다.

## 결론과 현재 상태

전체 재작성은 필요하지 않다. 기존 도형 계산, 고유 ID 편집, 누적 변경, 타일별 상태, Undo·프리셋을 재사용한다. **도형의 영역 → 지형 재료 → 구조물 배치**를 분리하는 확장이 필요하다.

| 요청 | 현재 동작 | 다음 구현 |
|---|---|---|
| 원형/자연스러운 원형 | 정확형 기본, 요청 시 경계 굴곡 지원 | 텍스트 연속 편집 회귀 유지 |
| 삼각주·해안 변형 편집 | 월드 연결을 유지하며 일반 강·해안으로 복귀 | 다른 특징의 실제 생성 검사 확대 |
| 특징 추가 조건 / 내부 특징 제거·복원 | 실제 Odyssey·VLE 정의와 생성기 조건으로 공통 검사 | 다른 모드 조합은 별도 실생성 검증 |
| 특정 영역 용암 채움 | 아직 미지원 | 실제 TerrainDef 기반 재료 목록과 채움 처리 |
| 섬 안에 유적 배치 | 아직 미지원; 밀도 조절만 존재 | 공간 제약과 지원 구조물 생성기 연결 |
| 임의 모드 지형/구조물 | 정의가 있다는 사실만으로 지원되지 않음 | 활성 모드의 정의를 검증된 재료·생성기 목록에 연결 |

“모든 텍스트 요청”은 지원 항목을 체계적으로 늘려가는 방향이다. 설치되지 않은 콘텐츠나 임의의 게임 동작을 무제한 생성한다는 보장은 아니다. 지원하지 않는 요청은 무엇이 부족한지 설명하고, 다른 결과로 몰래 대체하지 않는다.

## 1. 기존 특징을 유지·제거·복원

이번 구현은 `actual_tile_features`로 원래부터 있던 특징까지 전달한다. `remove_mutators`는 개별 특징, `remove_categories`는 종류 전체의 생성 제외, `restore_categories`는 그 제외 해제다. 잘못된 이름과 모순된 요청은 전체 변경을 거부한다. 기존 저장의 비활성 모드 제거 기록은 다른 편집을 막지 않는다.

사용자는 이후 “내륙에서 해안같은 건 만들면 안된다고 생각하는데”, “삼각주같은 건 강이 있을 때만 가능한거고 등등. 그런 식으로”라고 지정했다. 근거: `agents/main/log/2026-09-13-1357-mapgenai.md` §2026-09-13 — 월드 연결 보존 정책 구현 승인 [decision] (프로젝트 루트 기록).

이에 따라 이전의 강·해안 전체 생성 제외 방식은 **월드 연결 보존 정책으로 대체**한다. 삼각주·피오르드 등 변형만 제거하면 일반 강·해안이 남는다. 강 방향과 기존 해안 방향은 편집할 수 있고, 내부 호수·오아시스 등은 실제 지리·바이옴 조건이 맞으면 추가한다.

`FeaturePolicy`는 상속·외부 XML 패치 이후의 실제 정의와 생성기 검사를 사용하며 프롬프트 후보와 backend 계획·프리셋에서 같은 환경 조건을 적용한다. 자연 출현 확률, 기존 특징과의 자기 중복 판정, 랜드마크 추첨 제한은 환경 조건과 분리한다. 실제 특징 목록을 수정하되 월드 랜드마크 이름·아이콘을 재배치하지 않는다. 기존 자연 특징은 현재 유지 중인 경우 보존하고, 제거 후 재추가·복원에는 현행 조건을 검사한다.

종류 제거는 해당 TileMutator를 제외하는 처리다. 바이옴·기본 생성기·별도 외부 모드가 같은 효과를 다시 만드는 경우까지 모두 제거한다고 주장하지 않는다. [조건 정책 구현·검증](analysis/2026-09-13-feature-policy/report.md)에 구체적 범위를 기록한다.

## 2. 영역을 재사용할 수 있게 분리

현재 composite SDF가 계산한 영역을 채움뿐 아니라 구조물 배치에도 사용한다. 새 그림/팔레트 엔진은 만들지 않는다. 영역은 안정적인 ID로 저장하고, 합집합·차집합·섬 구멍·자연스러운 경계를 그대로 재사용한다.

예를 들어 “용암 호수 가운데 섬”은 용암 영역과 섬 영역의 차집합이며, “그 섬에 유적”은 같은 섬 ID를 참조한다. 유적이 섬의 바깥 사각형이나 용암 위에 놓이지 않도록 **전체 건물 면적이 실제 영역 안에 들어가는지** 검사한다.

## 3. 지형 채움 재료 목록

현재 7종 문자열과 비옥도 값에 고정된 채움 처리를 재료 목록으로 분리한다. 기존 `water`, `soil` 등 별칭은 보존하고, 저장에는 숫자 인덱스 대신 안정적인 재료 이름을 쓴다. 실행 시 활성 정의에서 실제 TerrainDef를 해석한다.

- 첫 대상: 기존 7종과 Odyssey 용암. 게임에 `LavaDeep`, `LavaShallow`, `CooledLava`가 존재하는 것을 로컬 정의에서 확인했다.
- 정의의 존재와 완성된 지원은 구별한다. 특히 얕은 용암은 임시 지형의 수명·전환 동작을 조사한 뒤 포함 여부를 결정한다.
- DLC/제공 모드가 없으면 요청 단계에서 안내한다. 모르는 재료를 물로 바꾸지 않는다.
- 채움 결과가 다른 생성 단계에 덮어써지는지, 통행·강 흐름·다리와 충돌하는지 실제 맵으로 확인한다.

완료 기준: 용암 원/고리/자연스러운 경계, 가운데 섬 보존, 재료만 바꾸기, Undo·프리셋·Scribe, DLC 없는 경우의 오류, 기존 물/토양 결과 보존.

## 4. 구조물 배치 계획과 생성기

구조물 요청은 종류, 개수, 대상 영역, 안/근처/가장자리 같은 관계, 크기·회전 제약으로 저장한다. 도형 이동·삭제에 따른 참조도 처리한다. “유적 밀도”와 “특정 섬 위 유적”을 서로 다른 기능으로 취급한다.

먼저 부서진 벽·바닥으로 이루어진 단순 폐허 한 종류를 지원하고, 검증된 생성기를 차례로 연결한다. 고대 위협·주둔지·퀘스트 구조물은 전리품·세력·위험·퀘스트 상태가 연결될 수 있으므로 임의 Def를 모두 실행시키지 않는다. 외부 모드는 지원 생성기를 등록하는 방식으로 확장한다.

공간이 부족하면 크기 축소 허용 여부를 확인하거나 배치 실패를 명시한다. 다른 위치로 옮기고 성공했다고 하지 않는다. 산·물·용암, 맵 가장자리, 다른 구조물과의 충돌을 검사하며 같은 seed의 재생성이 안정적이어야 한다.

완료 기준: 섬 안/북동쪽/산 가까이/여러 개 배치, 전체 면적 포함, 공간 부족, 순차 이동·삭제·되돌리기, 생성 실패 후 정리, 정의 비활성 상태의 안내.

## 5. 요청 해석과 실행 결과를 함께 평가

지원 기능 목록을 프롬프트와 검증기에서 공유한다. AI가 그럴듯한 문장을 답한 것만으로 성공 처리하지 않는다. 요청 → 계획 → 실제 TerrainDef/건물 위치를 비교하고, 미지원·부분 적용·완료를 구분한다.

실제 댓글 요청, 이번 자연어 요청, 기존 지형 보존을 묶은 반복 편집 사례를 회귀 목록으로 유지한다. Gemini 3.8을 기준으로 먼저 검증하고, 사용자가 선택할 수 있는 하위 모델은 별도 결과로 기록한다. Fable 재허용 전까지 추가 Claude 자문은 호출하지 않는다.
