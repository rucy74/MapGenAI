# MG32 — 선택형 추천 취향 문답 (적용 대기)

## 범위와 현재 상태

- 사용자 요청: 즉시 추천과 객관식 취향 문답을 선택하게 하고, 특별한 지형 선호를 물으며 플레이어 의견과 Claude Opus 5.5 자문을 참고한다.
- 원본 기준: `dev` / `1e33b8dcbc174c6c97ec41431ea0379ae300080c`. 이번 구현은 이 커밋의 작업 복사본에만 존재한다. 원본 프로젝트·설치 위치는 이번 세션의 쓰기 허용 범위 밖이다.
- 원본 `dev`, `main`, `dist`, 설치된 DEV/일반판, 사용자 설정은 수정하지 않았다. 이미지 입력은 계속 비활성이다. 지형 생성기와 기존 추천/검증 규칙은 수정하지 않았다.
- Claude 자문은 **미완료**다. Bridge는 설치된 CLI 2.1.138이 지원하지 않는 `--restricted` 옵션으로 실패했다. 도구를 모두 비활성화하고 모델 ID `claude-opus-5-5`를 명시한 별도 CLI 호출도 답변 없이 종료했다. 유효한 자문 내용이나 실행 모델 확인 결과가 없으므로 Opus 검토 완료로 취급하지 않는다. Fable 호출 없음.

## 질문 구성

지형 이름을 외우지 않아도 답할 수 있도록 배치와 사용감을 묻는다. 기본 5문항, 독특한 지형을 선택하면 6문항이다.

| 질문 | 선택지 |
|---|---|
| 가장 중요한 것 | 넓은 건설 공간 / 방어하기 편한 배치 / 보기 좋은 풍경 / 상관없음 |
| 산의 배치 | 탁 트인 생활 공간 / 한쪽 산과 반대쪽 평지 / 흩어진 작은 산과 언덕 / 부분적으로 감싸는 산 / 상관없음 |
| 추가할 물의 양 | 기존 물만 / 작은 연못 / 호숫가 생활 / 상관없음 |
| 특별한 지형 선호 | 익숙한 자연 / 평범한 안과 독특한 안 비교 / 독특한 풍경 위주 / 상관없음 |
| 특별함의 방향 — 조건부 | 산이 만드는 공간 / 물가의 풍경 / 열린 땅의 작은 포인트 / 상관없음. 앞선 답과 충돌하는 산·물 선택은 숨긴다. |
| 실제 지형 특징 | 어울리는 특징도 검토 / 새 특징 없이 모양과 배치에 집중 / 상관없음 |

특별함은 불편한 건설 공간이나 막힌 출입로를 감수한다는 동의로 해석하지 않는다. 실제 온천·유적 등은 설치된 콘텐츠와 타일 제약, 현재 특징과의 충돌 검사를 통과해야 한다. 기존 물만을 골라도 기존 강·바다를 제거하지 않는다. 해안과 세계 강의 새 연결을 만들겠다고 약속하지 않는다.

## 플레이어 의견을 반영한 근거

대표성 있는 설문이 아니라 공개 게시글의 정성적 참고다. 여론 비율이나 특정 취향의 우세는 추정하지 않았다.

1. [아름다운 칼데라 지도에 대한 반응](https://www.reddit.com/r/RimWorld/comments/1tq1jzz/this_is_possibly_the_most_beautiful_maps_ive_seen/): 미관과 방어를 좋아하는 의견과 산이 건설 공간을 많이 차지하고 바깥 출입이 불편하다는 의견이 함께 있다. 그래서 미관·공간·방어 우선순위와 특이한 지형 선호를 분리했다.
2. [좋아하는 기지 지형 토론](https://www.reddit.com/r/RimWorld/comments/1vkmtdo/whats_your_favorite_terrain_to_build_a_base/): 산과 큰 강, 해안, 열린 기지 등 여러 선호와 같은 지형을 반복해서 고르는 사례가 있다. 하나의 고정된 추천 조합을 강제하지 않고 산·물·특별함을 따로 수집한다. 지형 조건과 모드 기능에 관한 댓글을 게임 엔진의 근거로 사용하지 않았다.
3. [Geological Landforms 페이지](https://steamcommunity.com/sharedfiles/filedetails/?id=2773943594)는 이번 직접 조회가 429로 실패했다. 해당 페이지의 새 댓글을 전수 확인했다고 주장하지 않는다.

## 구현과 회귀 보호

- 첫 화면: `바로 추천받기` / `취향에 맞춰 추천받기`. 자유 입력은 계속 가능하다. 대화 도중에도 제목줄 `취향 문답`으로 열 수 있다.
- 문답은 독립 모달 창이다. 문답의 답을 기존 후보 번호로 오인하거나 후보 이미지가 채팅을 가리는 문제를 피한다.
- 질문 선택·뒤로·건너뛰기·조기 완료·취소는 로컬 처리다. 모델 호출이나 맵 상태/Undo 변경 코드가 없다.
- 이전 답을 바꾸면 뒤의 답을 초기화하여 숨겨진 분기의 낡은 취향이 남지 않는다. 같은 답으로 돌아가는 경우에는 기존 답을 유지한다.
- 최종 요약에서 추천받기를 눌러야 기존 `SendText` 경로로 들어간다. 기존 후보는 이때만 폐기한다. 기존 입력 초안은 유지한다. 후보 생성·호환성 검사·그림·선택·후보 수정은 기존 경로를 재사용한다.
- 질문용 API 호출은 0회다. 최종 추천은 기존 추천 파이프라인을 한 번 시작하며, 기존 오류 수정/요약/fallback이 작동하면 추가 호출이 생길 수 있다. 항상 유료 호출 1회만이라고 보장하지 않는다.
- 한글/영어 질문과 설명을 제공한다. 내부 식별자를 플레이어의 선택지로 표시하지 않는다.

## 실제 검증

- `dotnet build dev/Source/MapGenAI.csproj -c Release -v quiet`: 오류 0. 기존 자동 AssemblyVersion 경고 및 네트워크 제한에 따른 NuGet 취약성 정보 조회 경고가 있었다.
- `dotnet run --project dev/Source/Tests/TextToMap.Tests.csproj -c Release --no-build -- regression`: **230 PASS / 0 FAIL**. 기존 221개와 새 문답 검사 9개. 산·물·특별함 80조합, 이전 답 변경/숨겨진 답 폐기, 같은 답 재방문, 8,000단계 탐색, 조기 완료/취소/중복 제출, 한영 요청 구분을 포함한다.
- 별도 읽기 전용 코드 검토: 확정 결함 없음. 검토자는 Verse 창 입력 처리까지 대조했다. 이것은 실게임 입력 테스트가 아니다.
- `guide-design-ko.png`는 실제 질문 데이터로 만든 **구성 예시**, 게임에서 찍은 스크린샷이 아니다.
- 아직 하지 않은 것: 실제 게임 내 작은 화면/클릭/Enter/취소 테스트, 실제 공급자에서 취향 반영 결과 지도 확인, Opus 5.5 자문 완료, 원본 적용·커밋·push·DEV 설치. 과거 MG31의 실게임 성공을 이번 결과로 재사용하지 않는다.

## 적용 후 확인할 흐름

1. 바로 추천받기 및 `그냥 추천해 줘`가 기존처럼 후보를 내고, 선택 전 맵을 바꾸지 않는지.
2. 넓은 공간 + 열린 땅 + 기존 물만 + 독특한 안 비교: 물가/산 중심 추가 질문이 숨겨지고, 열린 땅의 작은 포인트를 비교하는지.
3. 산이 감싸는 곳 + 작은 연못 + 독특한 풍경: 내부 건설 공간과 출입로가 남는 후보인지. 후보 그림으로 판단해야 한다.
4. 문답 취소/X/뒤로/조기 완료가 현재 후보·맵·Undo·입력 초안을 보존하는지. 문답 중 Enter가 부모창 요청을 보내지 않는지.
5. API 대기 중 문답을 열 수 없는지, 부모창을 닫으면 문답도 닫히는지. KO/EN 및 UI 배율을 바꿔 스크롤·하단 버튼을 확인한다.
6. 해안 없는 타일에서 세계 해안이 생기지 않는지, 기존 강과 특징을 지키는지, 온천 등 실제 특징은 충돌 없는 경우만 제안하는지.

이 검증 전에는 설치/배포 완료로 취급하지 않는다.
