# 짧게 요청하고 그림으로 확인하기

로컬 DEV 검증용. 원본 게임 설치는 아직 끝나지 않았다. 아래는 실제 모델을 통해 확인할 문장이며,
이 문장들이 이미 실시간 API에서 통과했다는 뜻은 아니다. 이번 환경의 API 요청은 연결에 실패했다.
각 시작 요청은 초기화한 맵에서, 번호가 이어진 요청은 같은 맵에서 시험한다.

## 설명을 최소화한 첫 요청

1. `자연스러운 분지 만들어 줘.`
2. `안쪽 평지만 조금 더 넓혀 줘.`
3. `출구만 동쪽으로 옮겨 줘.`
4. `안쪽에 비옥한 토양을 70%만 채워 줘.`
5. `그 안에 작은 폐허 하나 넣어 줘.`

분지에는 비대칭 산벽과 넓은 내부가 있어야 한다. 2번은 같은 산벽 안의 평지만 넓히고,
3번은 다른 영역·토양·구조물을 다시 만들지 않아야 한다. 70%는 보호 대상을 제외한 적격 칸 기준이다.
되돌리기와 저장/불러오기도 확인한다.

새 맵에서 각각:

- `넓고 자연스러운 골짜기 만들어 줘.`
- `서쪽에 산기슭 만들어 줘.`
- `예쁘고 정착하기 좋은 맵 추천해 줘.`

골짜기는 좁은 직선 틈이나 같은 폭의 두 산벽이 반복되는지, 산기슭은 같은 간격의 뾰족한 톱니나
반듯한 홈처럼 보이는지 살펴본다. 주된 정착 공간이 충분한지도 그림과 실제 생성에서 판단한다.
모든 변형이 취향에 맞는다는 보장은 없다. 마음에 들지 않으면 후보 수정 또는 다시 추천받기를 쓴다.

## 타일과 기존 맵 보존

- 평지·건조 지대에서 `그냥 추천해 줘.`: 거대한 산벽/호수나 보너스 특징 묶음을 당연하게 추가하지 않는지.
- 산악 타일에서 같은 요청: 산에 둘러싸이더라도 넓은 정착 공간이 남는지.
- 기존 강·해안 타일: 원래 강/바다 연결이 남는지. 보존된 물을 가로지르는 동선은 별도 확인한다.
- 이미 편집한 맵에서 `추천해 줘.`: 기존 배치를 지우지 않고 보완안을 내는지.

## 예전 결과 확인

- 기존 자연지형 프리셋을 불러온다. 같은 타일/시드에서 산과 내부가 예전처럼 나와야 한다.
- 기존 분지에 `평지만 조금 더 넓혀 줘.`: 새 배치 방식으로 자동 전환되지 않아야 한다.
- 명시적으로 `이 분지를 새 자연스러운 배치로 다듬어 줘.`: 해당 지형만 바뀌는지.
- 정확한 원/별/하트/도넛, 산에만 뚫는 출구, 직선 흙길과 강 위 다리의 기존 예시를 표본으로 확인한다.
