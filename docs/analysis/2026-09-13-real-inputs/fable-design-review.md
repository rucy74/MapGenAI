## 코드에서 확인한 사실 (제안과 구분)

- **폴리곤 경로의 구조적 한계**: `ImageInterpretation.cs:20`은 후보당 32영역·64정점으로 제한합니다. before.png는 작은 산 덩어리가 20개 이상, 강은 굽은 가는 선입니다. 이 예산으로는 병합·생략이 필연이며, 모델 성능과 무관한 스키마 한계입니다.
- **팔레트 경로는 실제 이미지에 사실상 무용**: `ImageTextureCodec.cs:99`의 거리 임계 3600은 자체 프리뷰 팔레트 전용입니다. 실제 Map Preview의 회청색 강(약 110,130,150)은 가장 가까운 'N'(150,150,150)과도 거리 4500이라 '미인식'이 됩니다. 미인식이 'N'(자연 유지)으로 접히므로 실패가 조용히 사라집니다.
- **리사이즈가 최근접 샘플링**: `ImageTextureCodec.cs:81`은 픽셀 하나만 집습니다. ai-map.png(1250px→128)는 약 10픽셀 중 1개만 보므로 나무·자갈 텍스처가 소금후추 잡음으로 들어갑니다. 비전 전송용 768px 축소에도 같은 함수를 써서 모델 입력도 열화됩니다.
- **soil 고도 보존**: `ImageMapData.cs:95-96`은 M/W/S만 고도를 쓰고 토양류는 fertility만 씁니다. `GenStepPatches.cs:41`에서 hill_amount 오프셋이 먼저 전체에 더해지므로, 이미지의 평지가 생성 노이즈 산과 hill_amount 둘 다에 노출됩니다.
- **inset 미처리**: landform_07.jpg 우하단 "Gorge" 범례 박스를 자르는 로직이 없습니다. 팔레트 경로는 이를 지형으로 읽고, 폴리곤 경로는 모델 재량에 맡깁니다.
- **UI에 겹침 비교 없음**: `Dialog_ImageMap.cs:82-87`은 원본과 분류도를 나란히만 그립니다. 경계 어긋남을 눈으로 판정할 오버레이가 없습니다.

## 1. 대안: 코드가 영역 추출, 모델은 라벨만

제안 파이프라인(새 ML 의존성 없음, C#만):

1. **박스 필터 축소**로 격자(최대 128) 생성. 현재 Resize를 면적 평균으로 교체.
2. **거친 색 양자화**: RGB를 채널당 16단계로 binning하고 빈도 상위 K개(K≤8)를 대표색으로, 가까운 빈끼리 병합. 각 셀을 최근접 대표색 클러스터에 배정.
3. **3×3 최빈값 필터** 1~2회로 텍스처 잡음 제거. 작은 연결 성분(면적 < 4셀)은 이웃 클러스터에 흡수.
4. 모델에는 **원본 축소본 + 클러스터별 색 견본과 마스크 썸네일**을 보내고 스키마를 `{"clusters":[{"id":0,"label":"mountain","notes":""}]}`로 축소. 클러스터 하나에 하나의 라벨만 답하게 함.

현재 폴리곤 방식과의 비교:

| 항목 | 폴리곤(현재) | 클러스터+라벨 |
|---|---|---|
| 기하 정밀도 | 32×64 정점 상한 | 격자 해상도 그대로 |
| 모델 오류 지점 | 수천 개 좌표 | K개 라벨 결정 |
| 약점 | 작은 덩어리 병합, 가는 강 끊김 | 그늘진 바위와 흙, 나무 캐노피와 풀이 색으로 섞일 수 있음 |
| 2.5급 모델 적합성 | 좌표 생성 부담 큼 | 분류만 하므로 유리할 것으로 예상(미측정) |

top_down이면 클러스터 경로를 기본으로, oblique는 기존 폴리곤 경로를 유지하는 분기가 가장 작습니다. 라벨 결과가 틀린 클러스터는 기존 RegionAt/Relabel 수동 수정으로 이미 고칠 수 있습니다.

## 2. 두 입력 유형 공통 적용과 최소 실측

같은 함수를 쓰되 파라미터만 다릅니다. before.png는 평면색이라 K가 작고 필터 0~1회, ai-map.png는 필터 2회와 소성분 흡수가 필요합니다. 첫 구현은 파라미터를 고정하지 말고 `(k, filterPasses)` 두 값만 노출하세요.

최소 실측은 이미 있는 `tools/provider-probe/RealImageBench.cs`에 다음만 추가하면 됩니다.

- 입력 3장 × 경로 2개(폴리곤, 클러스터) × 모델 2개(3.8, 2.5).
- 저장물: 원시 응답 텍스트, 파싱 성공 여부, 격자 PNG, 원본 위 50% 오버레이 PNG.
- 라벨 없는 지표: 물 셀이 원본에서 닿는 가장자리에 결과에서도 닿는가, 산 연결 성분 수, 클래스별 면적 비율.

원본 격자의 "정답"은 사람이 32×32로 손라벨한 3장을 쓰고, 그 이상의 IoU 수치는 내지 않는 게 안전합니다.

## 3. 이미지 기반 + 사용자 SDF 공존 규칙

상태 규칙 제안:

- ImageMapData에 `baseMode` 필드 추가. `overlay`(현재 동작)와 `base`. `base`에서는 토양류 라벨이 고도를 산 판정 임계값 아래로 **clamp**(`min(elev, 상한)`)합니다. 고정값 대입보다 clamp가 잔여 기복을 남겨 자연스럽습니다. 'N'은 두 모드 모두 손대지 않습니다.
- hill_amount 오프셋은 `base` 모드에서 'N' 셀에만 적용. 이미지가 지정한 셀은 이미지 값이 유일한 기준.
- 사용자 SDF 도형은 항상 이미지 뒤에 적용되어 이깁니다(현재 순서 유지). 즉 우선순위는 도형 > 이미지 > 생성 노이즈로 고정 문서화.

UX 규칙:

- 대화창에 "이미지 평지가 생성 산을 덮음 / 생성 산 유지" 토글 하나. 기본은 이미지가 기준이라는 사용자 가정에 맞춰 `base`.
- 적용 후 부모 대화창에 "이미지 기반 + 도형 N개" 표시. 도형 추가 채팅 시 프롬프트에 이미지 기반 존재를 알리는지는 이번 범위 밖 파일이라 확인하지 못했습니다.
- landform_07처럼 범례 inset이 있는 경우를 위해 "무시할 사각형" 입력 하나(정규화 좌표 4개)를 두면 팔레트·클러스터 경로 모두에서 해결됩니다.

## 4. 세 단계 합격/실패 근거

실행 전에 기준을 적고, 실행 후 아래를 그대로 저장합니다.

1. **원본→해석 격자**: 원시 응답, 파싱 오류 문자열, 영역/정점 수 또는 클러스터 수, 미인식 셀 비율, 원본 오버레이 PNG. 합격: 파싱 성공, 물 연속성 유지, 단일 클래스 아님, 손라벨 32×32와 클래스별 면적 차이가 정한 허용치 이내.
2. **격자→생성 Map Preview**: 생성 프리뷰 스크린샷과 격자를 같은 클러스터 루틴으로 분류한 뒤 면적 비율과 물 연속성을 비교. 이 단계는 모델과 무관하므로 실패하면 Apply 규칙 문제로 귀속.
3. **사람 확인 항목 3개**: 호수 위치 사분면, 강 진입·이탈 가장자리, 가장 큰 산 덩어리 위치. 각각 예/아니오로만 기록.

수치 없이 "잘 나왔다"는 문장은 남기지 않고, 손라벨 기반 수치는 "주관적 정답 기준"이라고 명시하는 것이 과장을 막습니다. 3.8과 2.5의 실제 차이는 이 기록이 쌓이기 전에는 단정할 수 없습니다.
