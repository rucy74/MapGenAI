## 구현

열린 비대칭 분지, 넓고 굽은 골짜기, 한쪽 산줄기와 이어지는 산기슭 평야를 새 `landform` 타입으로
추가했다. LLM은 종류·방향·규모 등의 매개변수를 정하고 C# 생성기가 관련된 산벽과 평지를 만든다.
제2 모델 호출이나 이미지 입력은 사용하지 않는다. 새 설명 규칙만큼 입력 프롬프트는 늘었다.

한 ID의 평지 폭, 분지 출구 폭/방향, 전체 위치/규모를 따로 수정할 수 있다. `variant`를 저장해
이동·수정 시 산줄기가 다시 무작위로 바뀌지 않는다. 다른 변형을 만들 때만 variant를 바꾼다.
월드 시드는 기존 자연 지형에 반영되지만 새 거시 지형의 변형은 명시적 variant가 결정한다.

`region_part:inside`는 생성기가 정한 평지를 가리킨다. 기존 70% 비율 채움·폐허 배치가 이 ID를
참조하며, 저장/불러오기·되돌리기도 유지한다. 열린 지형이므로 `enclosed`는 거부한다.
정확한 원/별/하트/도넛과 기존 composite·통로·도로는 기존 생성 경로를 유지했다.

추천 프롬프트는 타일/사용자 취향에 맞을 때 새 타입을 사용하도록 했으며 세 종류를 고정 추천하지
않는다. 실제 공급자가 이를 얼마나 잘 선택하는지는 별도 사용자 테스트가 필요하다.
Geological Landforms의 원본 생성기 통합이나 전체 지형 목록 구현은 아니다.

## 실제 맵·보존·시간

최종 n11 완성 맵에서 채울 수 있는 평지 **14,294칸 중 10,006칸(약70%)**이 실제 비옥토로
들어갔다. 폐허 한 개와 벽 19개가 생성됐고, 계획된 평지에 산이 생긴 칸은 0이었다.
완성 맵의 기본 건물/보호 대상 때문에 미리보기의 적격 칸 수와는 다를 수 있다.

같은 월드 타일/시드에서 기본 맵과 비교한 강 셀 집합 **9,082칸**, 바다 셀 집합 **9,213칸**은
각각 정확히 동일했다(소실0, 추가0). 일반 연못 등 모든 물 종류를 통틀어 불변이라고 주장하지 않는다.

250×250 맵에서 최종 생성 단계 약 **50~64ms**, 새 지형이 있는 미리보기 전체 약
**0.23~0.42초**, 분지·비옥토·폐허의 완성 맵 약 **4.88초**를 관측했다.

실행 중인 정착지 시뮬레이션은 테스트 harness에서 정지했다.

## 실패를 거쳐 수정한 항목

- 초기 검사에서 평지 마스크의 한 칸 가장자리와 실제 보행 가능 지면을 동일시했다. 이제 낮은
  경사면을 포함한 실제 높이로 연결을 판정하며, 별도 검증도 같은 결론을 확인했다.
- 독립 검토에서 발견한 대각선 산기슭 모서리 단절 2건을 바깥쪽 가지 길이 완화로 수정했다.
- 분지에서 다른 종류로 바꾸는 편집의 opening 잔여 값과 null 초기화 실패를 수정했다.
- n1은 테스트 타일 검색 조건 때문에 실패했다. n2/n4는 native crash로 완료되지 않았다.
  n3은 테스트용 DLL이 사용 중이라 복사에 실패했고 게임 실행 단계로 가지 않았다.
  이후 전용 mod/profile을 매 실행 분리하고 시뮬레이션을 정지한 작은 실행 단위로 검사했다.
  이 사실만으로 crash 원인을 확정하거나 장시간 안정성이 입증됐다고 보지는 않는다.
  초기 pure 로그와 실패 native 로그도 증거로 보관했다.
