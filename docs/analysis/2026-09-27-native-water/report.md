# 기본 생성 코드를 참고한 자연형 담수 — DEV

사용자 요청: “그래 좀 그렇게 좀 해 봐. 기본 생성 코드 좀 참조해 봐.”

기준은 `dev`의 `21e5614`, 복귀 태그는 `dev-before-native-generation-2026-09-27`이다. 일반판·main·dist·이미지 입력 정책을 바꾸지 않는다. 개발 측에서 같은 조건의 실제 생성 결과를 비교하여 제공한다.

## 무엇을 확인했고 바꿨는가

설치된 RimWorld 1.6 `Assembly-CSharp.dll`에서 고도·비옥도, 바위, 지면 패치, Lake/Oasis, 작은 섬 정리, 식물 생성 흐름을 확인했다. 이전 구현도 기본 맵 생성 위에서 작동했지만, 우리가 추가한 물의 윤곽·수심·물가는 자체 계산과 후처리에 많이 의존했다. 이번에는 **새로 추가하는 자연형 담수의 공통 경로**에 기본 생성 방식을 연결했다. 분지 전용 처리는 아니다.

| 기본 게임에서 확인한 원리 | 이번 적용 |
| --- | --- |
| Lake의 변형된 하나의 영역에서 깊은 물·얕은 물·물가를 구분한다. | 같은 물 윤곽으로 수역과 물가 범위를 정하고, 완성된 칸 배치에서 육지까지 실제 거리를 재어 얕은 가장자리를 만든다. |
| 크고 작은 좌표 변형을 겹쳐 윤곽을 만든다. | 실제 `MapNoiseUtility.AddDisplacementNoise`를 사용하되 작은 연못·가느다란 물에 맞게 크기를 조절한다. 접힘과 칸 단위 틈을 줄이려고 여러 작은 변형으로 나눈다. |
| 물가 전용 바이옴/특징 재료가 있다. | `DeepFreshWaterTerrainAt`, `ShallowFreshWaterTerrainAt`, `LakeshoreTerrainAt`, `ShouldGenerateBeachSand`를 사용한다. 모든 물가에 진흙을 강제하지 않는다. |
| 지형 생성 뒤 해당 땅에 맞는 식물이 자란다. | 주변 원래 지면과 기본 식물 종류·적합성 규칙을 유지한다. 새 물가의 식생 가중치를 임의로 높이지 않는다. |

원본 Lake worker 자체를 작은 연못마다 실행하지 않는다. 원본은 전체 맵 고도를 지우고 호수 중심을 변경하며 DLC/타일 조건도 전제한다. 고도 생성 뒤 지면을 완성하는 순서는 유지하고, 지정한 영역만 수정한다.

기본 지면 생성의 `TerrainPatchMaker`는 작업 후 정리된다. 나중 단계에서 `TerrainFrom`을 다시 호출하면 원래 땅을 복원하는 대신 새 잡음을 만들고 난수 순서를 바꿀 수 있어 사용하지 않았다. 주변 원래 지면을 보존하는 편을 택했다.

## 기존 기능과의 경계

- 새 자연형 담수 추가에는 저장되는 `water_profile:native`를 기본 적용한다. 기존 저장에서 이 값이 없거나 `legacy`이면 이전 렌더를 유지한다. 이동·작은 수정만으로 기존 물을 자동 교체하지 않는다.
- 정확한 원·사각형 등은 이전 경로를 유지한다. 새 자연형의 일반 물/깊은 물은 안쪽 수심을 나누고, 명시한 얕은 물은 전부 얕게 유지한다.
- 선택된 자연형 수심과 표면 효과는 별개다. 이미 native인 물에서 `details:none`으로 바닥·식생 효과를 끄더라도 물 윤곽·수심을 바꾸지 않는다.
- 강·바다 연결과 도로 보호는 유지한다. 명시 재료·비율 채움 전체 영역·건물·기반·바위·지붕·특수 지면은 물가 장식으로 덮지 않는다. 새 지형을 놓을 공간이 없을 때 기존 보호물을 지우는 방식으로 해결하지 않는다.
- 온천·용암·염수 등은 이번 일반 담수 처리에서 제외한다.

기존 저장을 그대로 재생성하면 새 표현이 자동으로 나타나지 않는 것이 의도다. 새 자연형 물 요청으로 확인하거나, 기존 물의 윤곽과 수심도 새 방식으로 바꾸라고 명시해야 한다. 실제 모델이 그 후속 지시를 항상 맞게 해석한다는 새 API 검증은 이번에 하지 않았다.

## 실패를 통해 수정한 부분

처음의 약한 윤곽은 둥근 타원에 가까워 미관 완료로 인정하지 않았다. 원본의 큰 변형을 작은 지형에 직접 적용한 후보03은 706개 검사 중 416개가 실패했다. 후보04는 32개, 후보05는 6개가 남았다. 후보05에서는 연결성은 모두 통과했지만 눌린 호수의 얕은 가장자리가 지나치게 넓어 깊은 물이 사라졌다. 최종본은 실제 수역의 두께에 맞춰 가장자리 폭을 제한한다. 실패 원자료와 중간 그림을 보존했다.

최초 비그래픽 실행은 실제 지형 데이터가 생성되어도 회색 PNG가 나와 화면 근거에서 제외했다. 한 번의 실패한 probe 빌드 뒤 예전 probe가 실행된 결과도 무효로 표시했다. 이후 빌드 성공을 따로 확인하고, 소스가 DLL보다 새로우면 실행기가 거부한다. 최종 화면 비교는 그래픽 모드에서 얻은 실제 Map Preview PNG만 사용한다.

## 남는 한계

물가와 수심의 연결을 개선한 작업이다. 전체 맵의 미관, 자연스러운 물의 배치, 기존 강/호수의 실제 윤곽을 모델이 참조하는 편집, 과도한 산 삭제나 추천 구도까지 모두 해결한 것은 아니다. 원본 RimWorld 자체도 침식·유체 시뮬레이션으로 지형을 만들지는 않는다.

기본 Lake/Oasis는 서로 다른 위치와 크기로 생성되므로 참고 이미지로만 비교한다. 전후 비교는 같은 타일·시드·맵 크기·시간·설정에서 `water_profile`만 의도적으로 달리한다. Map Preview는 식물을 보여주지 않으며 이 그림은 게임 UI 캡처가 아닌 실제 미리보기 출력이다. 모든 모드 조합, 모든 바이옴, 플레이 중 체감 성능, 식물의 시각적 완성도와 사용자 미관 승인은 미검증이다. 이번 추가 API/Fable 호출은 0회다.
