# 추천 그림 피드백과 검증 계획

## 사용자 결정
현재 대화에서 사용자는 제안한 우선순위에 “그래 생각하는 대로 해 봐”라고 승인했다. 직전 제안은 “실패 후보 처리 → 그림을 보고 수정·재추천 → 필요할 때 AI 추가 질문”이다. 기존 결정 “기존에 잘되었된 게 안된다던가 그런 일이 최대한 없는 방향”을 유지한다.

## 구현 범위
- 생성 엔진/저장 형식/직접 편집은 유지한다. 추천 후보의 실제 preview authoring 실패를 적용 전에 차단하고 원인을 눈에 보이게 표시한다. 후보 번호는 고정하여 대화 참조를 보존한다.
- 미리보기 렌더 오류와 실제 배치 실패를 구분한다. 전자는 기존처럼 설명으로 선택할 수 있고, 후자는 수정/재추천만 가능하다. 미리보기 진행 중에는 완료를 기다린다.
- 기존 '다시 추천받기'에서 이유를 선택하거나 그대로 재추천한다. 후보마다 '수정' 진입점을 제공하며 '더 자연스럽게/산 줄이기/물 늘리기/물 줄이기/실패한 배치 고치기/직접 입력'을 기존 후보 편집 경로로 전달한다. 취소는 후보, 입력 초안, 지도, Undo를 보존한다.
- 후보 제목은 검증된 실제 변경 설명에서 도출한다. 모델이 약속하는 별도 제목을 신뢰하지 않는다.
- 선택적으로 AI에게 한 번만 취향 추가 질문(1~2문항, 문항당2~4선택지)을 요청한다. 시작 전 API 사용을 표시한다. 응답은 질문 데이터로만 읽고 맵 명령으로 실행하지 않는다. 사용자가 답변 확인 후 추천을 요청할 때만 기존 추천 경로로 보낸다. 실패/취소/오래된 응답은 기존 후보를 보존한다.
- 가능한 범위에서 신규 물 영역의 실제 물 생성 여부를 읽기 전용 검사한다. 수치 검사는 미관/전체 정착성 보장이 아니다. 자동 유료 재시도는 추가하지 않는다.

## 검증
기존 회귀 전체, 실패/대기/렌더 오류 구분, 한국어/영어 피드백의 새추천·후보수정 라우팅, 질문 JSON 제한·취소·원치 않는 명령 차단, 실제 기존 후보 응답 fixture를 사용한다. 실행환경 제약으로 native/API를 못 돌리면 미실행으로 기록하며 설치 완료라 하지 않는다. 코드와 기록은 먼저 현재 writable 복사본에 저장한다.
