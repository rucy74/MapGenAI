# 추천 그림 피드백 — 구현·검증 기록

## 상태와 범위

현재 사용자 승인 “그래 생각하는 대로 해 봐”에 따라 **로컬 개발 복사본**에 구현했다. 원본 저장소 `F:/Projects/Rimworld/active/mapgen_ai`의 dev 기준은 `1e33b8dcbc174c6c97ec41431ea0379ae300080c`다. 로컬 복사본의 직전 문답 commit은 `bd1e2d8bf4792b7ac8c414ce7f0e6af4ccace643`, 이번 작업 전 복귀 태그는 `dev-before-recommendation-feedback-2026-09-23`이다.

원본 저장소·설치 폴더가 현재 세션의 쓰기 허용 범위 밖이므로 원본 통합, GitHub push, DEV 설치는 미완료다. 일반 배포판·dist·원본 DEV·사용자 설정은 변경하지 않았다. 이미지 입력과 Fable은 계속 비활성 상태다. 요청받았던 Opus 5.5의 실제 답변은 받지 못했으며, 기존 bridge의 미지원 `--restricted`/CLI 빈 결과 문제를 해결한 것으로 주장하지 않는다.

## 변경

- 후보마다 `수정`, 확대 화면에 `이 후보 다듬기`. 자연스러움·산·물의 양·실패 배치 복구를 선택하거나 직접 입력한다. 전체 재추천에는 다양성 피드백을 제공한다. 이유 선택과 취소는 API를 호출하지 않고, 확인했을 때만 모델에 요청한다.
- 추가 객관식 질문은 사용자가 별도 버튼을 누를 때만 1회 API 요청한다. 최대 2문항/각 2~4개 선택지이며, 명령·추가 필드·잘못된 자료형·중복/너무 긴 문항을 거부한다. 답변 확인 뒤 추천 요청을 따로 보낸다. 기존의 시작 취향 문답은 계속 로컬 고정 질문이다.
- 후보별 수정/전체 재추천은 UI가 호출 모드를 고정한다. 자유입력의 직접 편집 표현이나 모델의 `generate` 응답으로 실제 맵에 적용할 수 없다. 취소 후 늦은 추가 질문은 버린다.
- 실제 미리보기 작성 보고서의 배치 실패는 `수정 필요`로 표시하고 버튼·번호 적용을 차단한다. 진행 중에는 검사를 기다린다. 렌더러 부재/그림 오류만으로 후보 자체를 실패 판정하지 않아 기존 설명 기반 선택을 보존한다. 번호는 그대로 유지한다.
- 변경한 도형의 물 의도를 덮어쓰기 전에 읽고 최종 TerrainDef와 대조한다. 25칸 이상 요청했는데 물이 0칸이면 차단한다. 콜백은 후보 범위에만 연결되고 일반 생성에는 없다. 생성 규칙/RNG/저장 형식은 바꾸지 않는다.
- 설명·확대 제목은 실제 변경 요약에서 추출한다. 별도 모델 제목을 실제 효과처럼 표시하지 않는다. 기존 채팅 공간을 줄이는 추가 버튼 행은 만들지 않았다.

## 검증

- 최종 회귀: **239 PASS / 0 FAIL**. [원문](verification/tests-r5.txt). 기존 문답·도로·다리·영역·대화 보존 검사를 포함한다.
- 제품 빌드 오류 0, 기존 버전 문자열/접속 불가 NuGet 취약성 조회 경고 2. [원문](verification/build-final.txt). 제품 DLL SHA256 `b5f55dd88137458ac9d26a7ad9c38ce22b38cf33f8174dcfd679bcde2f814ea6`.
- 별도 물리적 게임 복사본, disposable profile, `-batchmode -nographics`, 이전 실제 모델 응답 재생으로 **36개 native assertion PASS**. [결과](verification/native-headless-r7/result.json). 신규 공급자 요청 0, 재생/통제 응답 7회. 실제 후보 생성, 실패 도로 후보의 버튼/번호 차단, 정상 후보 적용·Undo, 문답, 취소·초안 보존, 질문 파싱, 잘못된 직접 적용 응답, 늦은 질문 무시, 흙에 덮인 물 의도, region_fill 관측을 포함한다.
- 독립 읽기 전용 코드 검토에서 발견한 전체 재추천의 직접 적용 가능성, 흙이 물 의도를 덮는 문제, 텍스처 예외가 배치 오류를 가리는 문제를 수정했다. 재검토에서는 새 확정 결함을 찾지 못했다. 이 검토는 Claude 자문이나 실행 검사로 세지 않는다.
- 이전 GUI 실행의 PNG와 이번 headless PNG는 픽셀이 다르다. 서로 다른 그래픽 실행환경의 비교를 보존 증거로 쓰지 않았다. [원래 비교 결과](verification/native-headless-r5/pixel-comparison.json). 이후 같은 headless 환경에서 직전 DLL `2c1458bf…`로 다시 생성하여 **6개 지도 각각 62,500픽셀이 모두 동일**함을 확인했다. [동일 환경 비교](verification/baseline-pixel-comparison-final.json), [기준 실행 18검사](verification/native-headless-r6/result.json). 이는 이 6개 입력/타일의 미리보기 보존 근거이며 모든 맵/모드 조합 보장은 아니다.

## 실패·제약

- 최초 테스트 2건은 예외 종류를 검사하는 새 테스트 helper의 오류였으며 수정 후 239개 통과했다. 이전 테스트 실행이 파일을 잠가 새 출력 디렉터리로 빌드했다. 실패 출력도 보존한다.
- headless r1은 Mono 런타임 누락으로 시작하지 못했다. r2/r3은 기존 테스트 폴더의 생성/복사 오류로 실행 전 중단됐다. r4/r5는 실제 실행했다.
- headless 그래픽 오류 로그를 먼저 보고 r4가 중단된 것으로 잠시 오판했다. 실제 결과 파일에서는 33개 검사가 완료되어 있었고 즉시 정정했다. 이후 늦은 질문·범위 복원·region_fill을 추가한 r5는 36개를 통과했다. Unity NullGfxDevice 셰이더/atlas 오류는 숨기지 않고 Player.log에 보존했다. 이 실행은 **GUI 레이아웃·글자 잘림 검증이 아니다**.
- 새 모델이 더 예쁜 추천을 생성하거나 추가 질문을 잘 묻는다는 품질 검증은 아직 없다. 이번 공급자 응답은 기존 기록/통제 응답이다. 마지막에 기존 두 인자 Enter/단일 인자 RegionGrid 호출의 바이너리 호환을 유지하도록 오버로드를 보존했고, 최종 DLL의 r7에서 36개 native 검사와 6개 그림 동일성을 다시 확인했다. 물 검사는 총합 기준이므로 작지만 남은 물, 여러 호수 중 하나의 누락, 연결성·건설 가능 면적·전체 특징 실현 여부는 보장하지 않는다.
- 모든 모드 조합·완성 맵·시각 UI·새 API 응답 확인이 남았다. [수동 확인 목록](manual-tests-ko.md).
- 테스트용 물리적 게임 복사본의 삭제 명령은 자동 승인 검토에서 `blocked by policy`로 거부됐다. 우회하지 않았으며 작업폴더 `work/mapgenai-headless-runtime`에 남아 있다. 원래 게임의 Mods 폴더에는 probe를 설치하지 않았다. [정리 대기 기록](verification/cleanup.json).
