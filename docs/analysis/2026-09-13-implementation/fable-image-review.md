## 문제 1. 폴리곤 형식의 가장 큰 맹점: 구조 검증이 의미 검증을 대신함

Region 수·꼭짓점 수·좌표 범위·퇴화 검사는 전부 "형식" 검사입니다. 과거 문자그리드가 반복행으로 통과했듯, 모델은 그럴듯한 좌표를 지어내도 이 검사를 모두 통과합니다. 특히 두 지점이 취약합니다.

- **oblique 입력의 좌표계**: 사진은 원근 공간인데 출력은 top_down 0..1 좌표입니다. 원근 변환을 모델의 머릿속에 맡기는 셈이라, 여기서 생기는 왜곡은 후보를 2개로 늘려도 잡히지 않습니다. 두 후보가 같은 오류를 공유할 수 있습니다.
- **가림 순서와 얇은 지형**: "뒤 region이 앞을 덮는다"는 규칙은 모델이 순서를 지킬 때만 호수 속 섬을 만듭니다. 순서가 뒤집히면 섬이 사라지는데 형식상 정상입니다. 또 강이나 좁은 해안은 64 꼭짓점과 256² 래스터에서 셀 폭 이하로 소실됩니다.

**검증법**: 같은 이미지로 API를 2회 호출해 후보 간 label별 IoU를 계산하고, 임계값 미만이면 품질경고를 강제로 붙이세요. 자기 일관성이 낮으면 재현이 아니라 해석입니다. 그리고 섬·강이 있는 실제 이미지 3장에 대해 사용자가 팔레트 도구로 직접 그린 정답 마스크를 만들어 label별 IoU와 좌우·상하 방향 검사를 돌리세요. 현재 계획의 합성 PNG는 로컬 nearest-color 경로만 통과하므로 vision 경로의 정확도는 0건 측정 상태입니다.

## 문제 2. 사용자 결정과 충돌하는 지점

- **"재현 우선, 불가능하면 해석 명시"와 top_down 단일 후보**: 위에서 본 지도도 모델이 틀립니다. 후보 1개에 불확실성 표기가 없으면 환각이 재현으로 제시됩니다. region 단위로 재현/추정 플래그를 요구하거나, 최소한 문제 1의 자기 일관성 점수를 표시해야 결정과 맞습니다.
- **미리보기와 적용 결과의 불일치**: "바탕격자 적용 후 기존 SDF 오버레이"인데 미리보기가 후보 격자만 보여주면, 사용자가 고른 그림과 실제 맵이 다릅니다. 기존 산 SDF가 이미지의 물을 덮는 경우가 대표적입니다. 미리보기는 합성 후 결과여야 합니다.
- **채팅 교정의 축소**: 사용자는 채팅 수정을 승인했는데 설계는 "안전한 label 교체부터"로 좁혔습니다. 단계 제한으로는 타당하지만 문서에 명시적으로 "이번 단계는 label 교체만, 외곽 이동은 미구현"이라고 적어야 조용한 범위 축소가 아닙니다.
- **GridBuilder 재사용**: 문자그리드 자체는 버렸지만 그 하류였던 GridBuilder를 재사용합니다. 과거 "부족한 칸 반복 채움" 로직이 그 안에 있는지 확인해야 합니다.

**검증법**: 미리보기 래스터와 Apply 후 타일 상태를 픽셀 단위로 비교하는 어설션 1개, Undo 후 원상태와 바이트 동일한지 확인하는 어설션 1개를 추가하세요. GridBuilder에는 셀 수가 부족한 입력을 넣어 예외를 내는지 봅니다.

## 문제 3. 최저 합격 조건이 정의되지 않음

4. 미리보기와 적용 결과 픽셀 동일, Undo 1회로 완전 복원.
5. 산출물·로그·테스트 출력에서 키 패턴 grep 결과 0건.
