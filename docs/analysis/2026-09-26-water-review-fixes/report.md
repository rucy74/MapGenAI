# MG39 — 물가와 취향 문답의 검토 후속

기준은 DEV `a4383a2`, 복귀 태그는 `dev-before-water-review-fixes-2026-09-26`이다. 사용자의 “그래 그럼 진행해”에 따라 앞선 Fable 자문을 실제 코드와 대조하여 수정했다. 이 구현 턴의 Fable·추천 API 호출은 0회다. 일반판·dist·main과 사용자 설정은 수정하지 않는다.

## 바뀐 동작

- 물가의 재질 거리를 계산할 때 가까운 별개 강·연못을 기준으로 삼지 않는다. 자연 효과를 허용한 영역의 담수에서 4방향으로 이어진 물만 사용하며, 탐색도 원래 영역의 6칸 범위와 명시적 보호 영역에 제한된다. 실제 생성 때 부드럽게 늘어난 물 가장자리는 따라간다. 범위 끝의 4~6칸에서는 물가 폭과 외부 식생 영향을 줄인다.
- 물가 Sand는 원래 모래이거나 바이옴의 기본 지형 목록에 있을 때, Gravel은 기본 목록에 있거나 바위 근처일 때 사용한다. 맞지 않으면 원래 Soil/Sand를 남긴다. Mud는 기존의 기본 지형·토양·식생·온도·강우 조건을 만족하는 물 바로 옆 일부에만 둔다. 산기슭 등 영역 내부의 기존 `Sample` 정책까지 바꾸지는 않았다. 원래 아무것도 칠하지 않던 Soil 분기는 보존 의도를 명시했다.
- 복합 도형의 물 판정이 실제 채움 우선순위를 따른다. union/sub/inter도 렌더할 수 있고, 최상위 dry fill은 물 fill을 덮는다. 중간 계산용 도형만으로 물이 있다고 판단하지 않는다. `water` 대소문자가 얕은 물 재료 해석을 다르게 만들던 문제도 수정했다.
- 취향 문답은 타일의 강·해안·호수 특징과 채팅으로 그린 연못을 구분한다. 구도 교체 중 ‘타일의 물만 유지’를 고르면 교체될 연못을 전제로 한 물가 질문을 하지 않는다. 원래 산과 직접 그린 산도 구분해 설명한다. 풍경·방어 선호가 명시한 새 산·물 금지와 보존 조건을 무효화하지 않도록 최종 요청에 적는다.

기존 정확한 도형, 저장된 `details=null`/`none`, 부분 수정은 자연 효과를 자동 활성화하지 않는다. 물·산 윤곽, 도로·기반·건물·특수 지면과 비율 채움의 전체 원본 영역을 보호한다. 이미 자연 효과를 사용하던 저장은 새 물가 정책의 영향을 받을 수 있으므로 모든 구버전 렌더가 같다는 뜻은 아니다.

### 이전 DLL과 직접 비교

같은 생성 결과의 기록된 작은 영역에서 물 9칸만 바꿨다. 원래 생성된 물은 바꾸지 않았다. 온대림과 건조 관목림 모두 이전 DLL은 별개 물을 추가하자 공통 마른 땅 **8칸**의 물가 재질도 바꿨다. 수정 DLL은 **0칸**이었다. preview와 완성 맵 모두 같았다. [칸별 비교](baseline-comparison.json)에 실제 인덱스와 공통 마른 땅 수를 남겼다. 이는 제어 입력에 대한 회귀 재현이며 사용자의 실제 강 배치 전체를 검증한 것은 아니다.

### 실패와 검사 한계

- 온대림 단일 방향의 연결 시험은 독립 BFS로 물 연결을 확인했지만 재질 변화는 없었다. 건조 관목림에서도 같았다. 이 위치에서는 바위에서 먼 자갈 제안이 바이옴 정책에 의해 보존으로 바뀌므로 ‘연결하면 반드시 바닥이 바뀐다’는 양성 검사 2개씩을 통과하지 못했다. [온대 실패](interaction-temperate-audit-01.json), [건조 관목림 실패](interaction-arid-audit-01.json)를 보존했다. 후속 시험은 고정 네 방향을 모두 조사해 기하학과 보호 조건을 통과하는 첫 위치들을 함께 사용했다. 서쪽은 조건을 만족하는 위치가 없어 그 사유를 기록하고, 서로 겹치지 않는 동·북·남 3곳의 49칸 영역을 전부 시험했다. 결과나 seed로 위치를 고르지 않았다. 연결했을 때 공통 마른 땅 5칸이 실제로 바뀌어 양성도 확인했다. 이 보완 시험은 앞의 실패를 삭제하거나 통과로 바꾸지 않는다.
- 문답의 최종 일반 지침에 추가된 `Scenery`까지 과거 선택 답변으로 간주한 테스트 substring 비교가 1회 실패했다. 현재 선택 요약과 해당 선택의 구체 문구를 확인하도록 바꾼 뒤 299개가 통과했다. 제품의 뒤로가기 상태 초기화 문제로 확인된 것은 아니다.
- 첫 Python 자식 PowerShell 실행에서 `Get-FileHash`를 찾지 못해, native 프로세스 생성 뒤 launch 기록 쓰기가 실패했다. 해당 실행의 PID와 복사된 제품/프로브 해시를 대조해 `started:null`, 복원 이유가 있는 기록을 남겼다. runner는 이제 실행 전에 .NET으로 해시를 계산한다. 복원된 실행은 `native-shore-near-water-01`이며 원래 시작 시간을 알아냈다고 주장하지 않는다.

## 직접 확인과 남은 작업

[수동 테스트 7개](manual-tests-ko.md) 중 먼저 1·2·5번을 확인하면 된다. 게임에서 **MapGen AI [DEV]**를 사용한다.

기본 문답은 준비된 선택지를 앞선 답과 설정에 따라 조정한다. API가 질문을 매번 만드는 방식은 아니다. 실제 모델이 최종 선호를 언제나 지키는지, GUI의 모든 화면 크기, 모든 바이옴·모드 조합, 최종 식물의 동일성은 이번에 검증하지 않았다. 빙토/한대림에서 바닥 변화가 0인 결과는 원래 바닥 보존이며 새로운 물가 표현을 실증한 것은 아니다.

물의 동그란 모양 자체, 기존 강·호수의 실제 윤곽을 추천 모델이 읽는 기능, 추천의 미관과 상위 배치 품질은 별도 후속이다. 이번 검사를 Geological Landforms 전체 수준의 품질 보장으로 보지 않는다.
